title: '메모리에 남기지 마라'
pubDate: 2026-10-21
tags: ['skill']
---

SBS에 있으면서 다양한 연령대의 선후배들과 일할 수 있었다. 특히 우리 IT 부서에는 진짜 **시니어** 선배분들이 계셨다. (우리는 직급으로 국장님이라고 불렀다.)

당시 국장님들은 서울대 물리학과, 부산대 경제학과 등 소위 명문대를 나오신 엄청난 재원들이셨다. 다만, IT 붐이 본격적으로 일어나기 전부터 컴퓨터가 좋아서 전산학의 길을 걸으셨던 분들이라, 요즘 세상에 쏟아지는 새로운 트렌드나 프레임워크에는 크게 관심이 없으셨다.

하지만 오랫동안 함께 부대끼며 일하다 보니 "**아, 역시 진짜 똑똑한 사람들은 체급이 다르구나**" 하고 감탄하게 되는 순간들이 찾아왔다.


특히 메모리 관리와 코드 스킬만큼은 기가 막히셨다. 생각해보면 그중 몇몇 분은 실제 메모리가 1MB이던 시절에 컴퓨터를 공부하셨던 분들이었다 ㅋㅋㅋㅋ.

그분들이 "**메모리에 웬만하면 남겨두지 마라**"라고 조언해 주신 적이 있다. 처음엔 하드웨어 최적화 이야기를 하시는 줄 알았는데, 그 이면에 담긴 진짜 의미를 듣고는 정말 머리를 한 대 맞은 것 같았다.

지적하신 건 이런 패턴이었다. `if`문이나 `while`문에 들어가기 한참 전에 임시 변수를 미리 만들어 두고 쓰는 것.


```js
const adminUser = users.find(user => user.role === 'ADMIN');
// .... 코드
if (adminUser) {
  sendAlert(adminUser.name);
}
// .... 코드
```

이런 식의 코드는 프로젝트가 커질수록 두 가지 치명적인 문제를 낳는다.

**첫째, 변수의 운명을 예측할 수 없게 된다.**

실무 코드는 결코 이렇게 짧지 않다. 상단에 선언된 변수가 스코프 끝까지 살아 있으면, 다른 개발자가(혹은 미래의 내가) 그 값을 어떻게 다룰지 알 수 없다. `let`이라면 중간 어딘가에서 재할당될 수 있고, `const`라도 객체라면 내부 값이 얼마든지 바뀔 수 있다. 살아 있는 시간이 길수록 오용될 여지도 커진다.


**두번째로 변수 선언부와 사용부가 점점 멀어질수록 인지 부하가 발생한다.**

RAM만 메모리를 아껴야 하는 게 아니다. **개발자의 머릿속(브레인) 메모리도 아껴야 한다.** 코드가 수백, 수천 줄 이상 길어질 때 상단에 선언된 임시 변수는 개발자의 머릿속에 계속 부담으로 남는다.(메모리 뿐만 아니라 머릿속에도...)

개발자는 백이면 백, 어느날 서비스에 문제가 생겨서 디버깅을 하게 된다. 그때 이 변수가 아래 로직 어딘가에서 변형되나?", "얘가 왜 아직도 이 스코프에서 살아있지?"를 끝없이 추적해야 한다.

결국 변수는 **최대한 늦게 만들고, 쓰이는 즉시 필요 없으면 소모해 버려야 한다.**

방법은 여러가지다. 

먼저 [블록 스코프](https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Statements/block)를 활용해서 변수의 수명을 필요한 만큼만 묶어둘 수 있다.

```js
{
  { // block scope
      const adminUser = users.find(user => user.role === 'ADMIN');
      if (adminUser) {
      sendAlert(adminUser.name);
    }
  } //
}
```

또한 값이 아니라 존재 여부만 필요하다면 조건문에서 바로 처리할 수도 있다.(우리 팀은 아래 방법을 권장한다)

```js
if (users.some(user => user.role === 'ADMIN')) {
  sendAlert('관리자 계정이 존재합니다.');
}
```

사실 함수(모듈)로 분리하는 게 가장 깔끔하다. 함수 스코프에 변수의 수명을 가두면 된다.

(시간이 지나면 다들 이렇게 안하더라..)

```js
function alertAdmin(users) {
  const adminUser = users.find(user => user.role === 'ADMIN');
  if (adminUser) sendAlert(adminUser.name);
}
```
이렇게 컴퓨터의 메모리도 아끼고, 코드를 읽는 사람의 두뇌도 아껴주어야 한다.

---
이런 관점에서 보면, 요즘 유행하는 신기술이나 프레임워크 트렌드에 조금 어두워 보이시던 국장님들의 진짜 내공이 보인다.(지금은 은퇴하셨지만)

새로운 라이브러리를 쓰는 법은 몇 달이면 배우지만, 이런 '**코드를 대하는 태도와 감각**'은 오랜 세월을 지킨 시니어만이 줄 수 있는 진짜 자산이 아닐까 싶다.
